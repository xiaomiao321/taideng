# 烧录说明

阅读指引：第 1 到 4 节按顺序做一遍就能烧好；第 5 节是不用图形界面的命令行烧法，备查。

固件有两份，在 GitHub Release 里下载：

- firmware_debug.hex：调试模式，配合调试上位机 BoardDebugMulti.exe 调电机、标定关节。调电机用这份。
- firmware_android.hex：安卓模式，接安卓核心板时用。

两份都可以直接烧，不需要先擦除。关节标定存在 Flash 的扇区 10 和 11，正常烧录不会碰到，换模式后标定还在。

## 1. 接线

板子先按平时的方式上电，[ST-LINK/V2](https://www.st.com/en/development-tools/st-link-v2.html) 只接三根线：

- SWDIO 接板上 PA13
- SWCLK 接板上 PA14
- GND 接板上 GND

板子已经单独供电时，不要再接 ST-Link 的 3.3V 输出脚。

## 2. 连接芯片

1. 打开 [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)，在右上角的下拉框里选 ST-LINK。
2. 下面的设置基本保持默认：Port 选 SWD；Frequency 用 4000 kHz，连不上就降到 1000；Mode 选 Normal；Reset mode 选 Software reset。
3. 点右上角绿色的 Connect。成功后按钮变成 Disconnect，下方 Target information 里的 Device 显示 STM32F40x/STM32F41x，Flash size 显示 1 MB。
4. 如果弹窗提示 ST-Link 固件太旧、问要不要升级，可以按提示升级，升级完重新插一次 ST-Link。

## 3. 烧录

1. 点左侧竖排图标里的第二个 Erasing & Programming，图标是一个向下的箭头。
2. 在 File path 后面点 Browse，选要烧的 hex。hex 文件自带地址，Start address 是灰的，不用填。
3. Verify programming 和 Run after programming 勾上，Skip flash erase before programming 不勾。
4. 点 Start Programming。几秒后弹出 File download complete，日志区最后显示 Verify OK 或 Download verified successfully。
5. 点右上角 Disconnect，然后按一下板上的复位键或者重新上电。

千万不要点的东西：Erasing & Programming 页右边的 Full chip erase 按钮、左下角的整片擦除图标，以及在 Erase selected sectors 里勾选扇区 10 或 11。这些操作都会擦掉关节标定，擦了就只能重新标定。正常的 Start Programming 只擦 hex 用到的扇区，是安全的。

## 4. 确认

用 USB 转 TTL 模块接 USART3：模块 RX 接板子 PB10，模块 TX 接板子 PB11，GND 相连，波特率 115200。注意不是接安卓核心板的那个串口。

- 调试模式：复位后串口助手里能看到 `READY BOARD_DEBUG 2`。之后关掉串口助手，用调试上位机连同一个 COM 口即可。
- 安卓模式：复位后能看到 `joints: N calibrated` 和 `protocol ready` 两行日志，N 是已标定的关节数。

## 5. 命令行烧录

装了 [xPack OpenOCD](https://github.com/xpack-dev-tools/openocd-xpack/releases) 的话，可以不开图形界面，在 hex 所在目录执行：

```powershell
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg -c "program firmware_debug.hex verify reset exit"
```

这条命令同样只擦 hex 用到的扇区，标定不受影响。从源码编译和用 VS Code 调试的方法见同目录的 [README.md](README.md)。
