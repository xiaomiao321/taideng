# App团队首轮集成交付说明：Robot SDK 0.3.0

交付资料修订：2026-10-03 D1。SDK和两款示例版本均为0.3.0，示例versionCode=3；主验证App源码版本为1.3.1。本文用于首轮集成、分工和验收讨论，资料更新不改变二进制版本。

已确认：先按原生Android准备；我方将提供同款RK3566板卡、摄像头和USB麦克风。团队最终语言、摄像头数量/型号、MCU配置与产品后台运行策略需在收件时确认。

## 1. 首轮目标

App团队在自己的机器人端APK中引用SDK，在交付板卡上完成预览、坐姿数据展示、USB语音数据展示、权限及前后台生命周期。双方用同一套实际状态和错误语义联调；后续产品页面、蓝牙/服务器业务和新增硬件沿用这条接口边界。

SDK为本地Android Library，由你方最终APK运行。我方负责采集/模型/串口协议与接口问题；你方负责正式页面、交互、权限流程、身份/历史记录、数据传输及服务端业务。家长端手机App通过你方蓝牙/网络链路接收数据，不直接运行RK3566 SDK。

## 2. 收到后先看哪些文件

1. 本交付说明：确认范围、硬件条件和首轮验收。

3. 本包SDK接入指南：查依赖、公共接口、权限、无线ADB和安装细节。
4. SDK数据与蓝牙对接.md：落实字段、时间戳、有效期与传输责任。
5. SDK0.3.0验证记录.md：了解已实际检查的内容；硬件控制另读两份MCU协议。

Wi-Fi设置、OTA、账号/学生/任务、历史统计与正式业务UI由App团队提供；主验证App中已有相关参考实现。SDK示例以能力接入为主，正式App可重新设计页面。

## 4. 硬件与构建基线

运行目标：RK3566、Android11/API30、arm64-v8a；已验证组合为RKNN Runtime2.3.2、板载RKNPU驱动0.8.8。最后一次记录的板卡显示为600×1024竖屏。供给App团队的固件、显示配置和外设应与双方确认的实机一致。

示例构建配置：JDK25、AGP9.3.1、Gradle9.5.0、compileSdk37、minSdk29、targetSdk30。源码接入另需NDK27.2.12479018、CMake3.22.1。示例build环境不要求你方盲目重构已有工程；收到你方AGP/Kotlin/界面技术栈后核对兼容性。

## 5. 首轮采用的公共接口与语义

| 模块 | App调用 | App消费 |
| --- | --- | --- |
| 版本/设备诊断 | RobotSdkInfo、RobotDeviceInfo.capture | SDK/系统/权限/USB元数据；Bluetooth flag只代表系统声明 |
| 角色设置 | CameraInventory.enumerate、CameraRoleRegistry.refresh/bind/resolve/unbind | BOUND/SESSION_BOUND/UNBOUND/MISSING/AMBIGUOUS/CONFLICT |
| 坐姿 | PostureRecognitionClient.start/stop/close、setThresholds | onBusinessResult或subscribeBusiness、latestBusinessSnapshot；onObservation用于关键点诊断 |
| 拍题 | QuestionCameraClient.start/stop/close、capturePhoto | CameraEvent、isPreviewActive、JPEG成功/失败 |
| 语音 | StreamingSpeechRecognizer.start/stop/close | SpeechRecognitionState、onFinalTranscript |
| 基础串口 | McuSerialController.start/refreshDevices/setLight/setMotion/stopMotion/pause/close | 连接、实际状态、McuCommandSubmission及onCommandResult |
| 扩展串口 | 按已验证capability开放；requestExtendedStatus查询 | 扩展状态与关节快照、UNKNOWN/陈旧状态 |
| 搜题 | PhotoSearchClient.solve/cancel/close | 是否受理及PhotoSearchState |

坐姿业务状态为NO_PERSON、INSUFFICIENT_KEYPOINTS、OBSERVING、PARTIAL、NORMAL、ABNORMAL。先检查快照CURRENT，再显示结论；EXPIRED/UNAVAILABLE清除实时结论。连续异常时长不是历史累计；sequence不是跨实例/重启全局ID。完整JSON字段与时钟语义以SDK数据与蓝牙对接.md为准，当前schemaVersion=1。

语音Listening.transcript用于持续刷新临时文字；onFinalTranscript用于最终片段。App按自身业务确认用户意图后再触发控制，不把临时转写直接变成运动命令。

串口accepted为SDK受理，ACK_RECEIVED为MCU接收，APPLIED需新的关联实际状态匹配目标；App按commandId跟踪。故障/过期/超时/断线应显示明确失败或不可用。STOP独立于普通按钮的忙碌门控；MCU仍负责本地限位和失联停止。

相机调用及SDK回调使用主线程；App文件/数据库/蓝牙/网络写入使用后台工作队列。App保持一个清晰的采集所有者，前台就绪后start，退后台先清前台标志，再MCU pause、相机/语音stop，最终销毁close和取消订阅。

终端App持续前台时可保持语音开启。产品若要求跨页面/后台持续采集，应明确上层所有者与Android运行策略，再验收资源与权限；首轮教程采用页面前台生命周期。

坐姿提示音由App按持续异常和冷却策略控制。JPEG来自预览尺寸，正式拍题图不带骨架/取题框；高分辨率拍照、自动透视矫正和安装方向适配需按实际产品要求另测。

## 7. 问题反馈格式

每次反馈包含：问题ID、SDK/App版本、AAR或源码接入、板卡固件/ABI/驱动、外设型号与数量、复现步骤、预期/实际表现、对应角色与状态、时间范围及脱敏日志。控制问题附commandId、受理/ACK/实际回读或超时结果；相机问题附枚举列表和角色绑定状态。

建议先由App团队用自己的APK复现，再在同一板卡用交付示例复测：两者都出现时共同排SDK/硬件；仅宿主出现时先核对接入、权限、生命周期和依赖。测试时避免两款App争用相机/麦克风。

图片、转写或用户信息只按双方确认的调试方式提供；反馈中不带API密钥。
